# 🎨 SVG Icon Collection

一个轻量级的 SVG 图标收藏与预览工具，用于集中保存常用 SVG 素材，方便日常网页设计和前端开发时快速查找、预览与下载。

本仓库会持续收集和更新图标。采用 **HTML + CSS + 原生 JavaScript** 构建，无需安装依赖、数据库或后台管理系统。

## 🚀 使用方法

### 在线使用

打开 [SVG 图标收藏页](https://coowinit.github.io/svg-icon-collection/)（需先在仓库中启用 GitHub Pages）。

1. 浏览页面中的 SVG 图标。
2. 在搜索框中输入图标名称或关键词，快速筛选。
3. 点击图标卡片下方的 **「下载」** 按钮，保存原始 SVG 文件。
4. 将下载的文件用于自己的网页、主题或前端项目。

支持中英文关键词搜索。按下 `/` 可以快速聚焦搜索框；在搜索框中按 `Esc` 可以清除搜索并退出。

### 本地使用

1. 下载仓库源码并解压，或使用 Git 克隆仓库。
2. 打开根目录的 `index.html`，即可浏览和搜索图标。
3. 如浏览器限制本地 `file://` 文件下载，可使用 VS Code **Live Server** 在本地启动页面。

## ➕ 新增或删除图标

为了便于长期维护，图标文件与展示数据分开管理。

**新增图标：**

1. **先完成下方的授权检查并记录来源**，确认允许将 SVG 公开上传、展示和提供原文件下载。
2. 将 SVG 文件放入 `icons/` 目录，文件名建议使用小写英文和短横线，例如 `new-icon.svg`。
3. 打开 `js/icons.js`，在 `ICONS` 数组中添加一条记录：

```js
{
  "file": "new-icon.svg",
  "name": "New Icon",
  "keywords": "新图标 example keyword"
}
```

4. 保存并刷新 `index.html`，确认图标能够显示、搜索和下载。
5. 将新增文件、图标清单及依法需要保留的许可/署名信息一起提交到 GitHub。

**删除图标：** 删除 `icons/` 中对应的 SVG 文件，并同步移除 `js/icons.js` 中的记录。

**字段说明：**

| 字段 | 用途 |
| --- | --- |
| `file` | SVG 文件名，须与 `icons/` 中的文件一致 |
| `name` | 页面上显示的图标名称 |
| `keywords` | 搜索关键词，可填写中英文词语 |

建议保持文件名唯一。新增图标不需要修改 `index.html`、`css/style.css` 或 `js/app.js`。

## 🛡️ 图标来源与授权管理

本仓库面向公开浏览和下载，**上传 SVG 原始文件属于重新分发**。只收录能确认有权公开分发的素材。以下规则用于降低风险，但无法保证任何资源绝对不存在第三方权利争议，也不构成法律意见。

### 收录前检查

- **优先收录：** 自行原创且没有使用受限制的第三方素材；或来源明确、允许重新分发原始 SVG 的开源图标。
- **核对许可证：** 区分“可在网站中使用”与“可将原始文件再发布给他人下载”。留意署名、保留版权声明、附许可证等条件。
- **记录证据：** 至少保存文件名、原始来源 URL、作者/项目、许可证名称及链接、获取日期；许可附带的版权信息和版本也应保存。推荐放在维护者自己的记录中，或以后增加 `SOURCES.md`，不要求在页面添加复杂功能。
- **来源不明时：** 不要仅因“免费”“网上找到”“AI 生成”或“修改过颜色/形状”就视为可以公开分发；待确认权利后再收录。
- **谨慎收录：** 公司 Logo、产品商标、受保护的角色或特殊标识。即使可下载，也不等于可以自由使用其商标、暗示品牌背书或再授权。
- **技术检查：** 不收录含脚本、事件处理器、危险外链或不明嵌入内容的 SVG。

### 现有素材的待核实事项

- **国家旗标：** 当前来自维护者提供的文件包；原作者、原始下载地址及许可尚未逐一核验。国家旗帜图案和具体 SVG 绘制文件的权利情况可能不同，不能仅依据“国旗”二字判断许可。
- **常用线性图标：** 为项目初始版本整理的 SVG；尚未建立逐项来源与授权证据。**不应将整套素材宣称为 CC0、MIT 或无版权限制。**

在来源确认前，建议暂缓将对应 SVG 作为“已获授权的可自由再分发资源”向第三方推广；如无法补齐授权依据，优先替换为来源可核实的素材或移出公开仓库。

### 许可证与仓库授权

- 仓库中的 HTML/CSS/JavaScript 代码与 `icons/` 下的 SVG 素材可能拥有不同版权归属和许可条件。
- 不要随意用一个仓库根目录 `LICENSE` 宣称所有第三方 SVG 都属于同一许可证。未来如需给代码加许可证，应明确其适用范围，并单独保留第三方素材的授权声明。
- 如收到权利人反馈，请核实具体文件、来源和授权依据；存在合理疑虑时先暂停公开分发相关文件，确认后再恢复或替换。README 声明不能代替真实许可。

## 🌐 GitHub Pages 部署

如需在线使用，可在 GitHub 仓库中打开 **Settings → Pages**：

1. 在 **Build and deployment** 中选择 **Deploy from a branch**。
2. 选择 `main` 分支和 `/(root)` 目录，保存。
3. 发布完成后，访问 `https://coowinit.github.io/svg-icon-collection/`。

后续更新并推送至已配置的发布分支后，GitHub Pages 会重新部署。

## 🔄 维护原则

- 以 **收藏、查找、预览、下载** 为核心，不增加不必要的复杂功能。
- 保留原始 SVG 文件，避免因展示需求而修改素材。
- 新增图标只需更新 `icons/` 和 `js/icons.js`。
- 尽量保持简单的目录结构，方便长期积累和迁移。
- 对每次新增的第三方 SVG 保留来源与许可证明；未知来源的素材先核实再公开。
